# PR を独立レビューする

リポジトリルートの `AGENTS.md`、`docs/development-workflow.md`、`docs/project-context.md` を適用する。
入力は Issue、PRまたは差分、base / head SHA、受け入れ条件、検証結果。
PRが未作成でもローカル差分をレビューできる。比較元や対象が不明なら確認し、対象を推測してレビュー済みにしない。

1. 実装者とは別の Agent / セッションかを明示する。同じセッションなら自己レビューと表示し、独立レビューの代わりに数えない。
2. 対象 head SHA と比較元を記録する。Issueと差分を読み、変更周辺のコード、呼び出し元、関連テストも調べる。
3. correctness / regression / security / architecture / unnecessary complexity / test coverage の6観点で確認する。既存の責務・依存方向、不要な抽象化、テストの境界条件も確認する。受け入れ条件、エラー経路、境界条件、互換性、データ整合性、変更に関係する権限・秘密情報の扱いを確認する。
4. 検証結果を照合する。必要な確認を実行できない場合は未確認と書く。テストコードの存在だけで成功と判断しない。
5. 指摘は具体的な発生条件、影響、ファイル・行、根拠、修正の方向を含める。実害の裏付けがない推測や好みは重大指摘にしない。
6. 変更後の再レビューでは新しい head SHA を記録し、修正が問題を解消しているかと追加変更の影響を確認する。

結果には次を含める。

- レビュー担当 / 独立性 / base・head SHA / 確認した範囲
- 指摘: `[P0–P3] 要約 — 場所 / 発生条件 / 影響 / 根拠 / 修正の方向`
- 実行した検証と結果、未確認の範囲、残るリスク
- 結論: 修正必要 / 指摘なし（確認範囲内）/ 情報不足

重大度は共通ワークフローの定義を使う。問題が見つからなければ指摘を捏造しない。
レビュー中はファイル変更・修正・コミット・マージ・外部投稿を行わない。読み取り・検索と副作用を確認した検証コマンドのみ使う。
自動修正、同期（書き込みモード）、スナップショット更新、依存導入は禁止。検証が対象ファイルや外部状態を変更する場合は実行せず未確認として報告する。
未コミット差分を含む場合はその旨と対象ファイルを記録し、head SHAだけをレビュー対象の証拠にしない。
