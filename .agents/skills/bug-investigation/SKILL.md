# 不具合を調査する

リポジトリルートの `AGENTS.md`、`docs/development-workflow.md`、`docs/project-context.md` を適用する。
入力は Issue、現象、再現条件、期待値。欠けている情報はコードやログで補い、確認できない値は未確認とする。

1. 再現前に調査計画を短く記録する。環境、バージョン、再現手順、頻度、影響範囲を集め、最小の再現方法を探す。
2. 観測結果と原因仮説を分ける。仮説ごとに判別できる検証を行い、支持・否定する証拠を記録する。
3. 再現しない場合は、試した条件と不足情報を報告する。原因を断定せず、追加の観測方法を提案する。
4. 原因が絞れたら、修正範囲、回帰リスク、再発を検出するテストを示す。調査だけの依頼では修正を勝手に適用しない。
5. 修正まで依頼されている場合は計画を更新して最小変更を行い、可能なら修正前に失敗し修正後に成功する回帰テストで確認する。
6. 共通ワークフローの検証と別Agentレビューへ渡す。根本原因の解消と一時的な回避策を区別する。

出力は「現象 / 再現と証拠 / 仮説と検証 / 原因の確度 / 修正方針 / 検証結果 / 残課題」。
本番データの変更や破壊的操作を再現手段として無断実行しない。ログは秘密情報を除いて共有する。
GitHubへの投稿は依頼・既存の許可がある場合に限る。
