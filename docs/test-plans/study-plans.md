この文書は、学習計画機能が要件と仕様を満たしていることを、何で・どこまで・いつ確かめるかを定める。
テストケースは機能仕様書の業務ルール（BR）と要件（FR / NFR）に対応させ、第8章で対応を一覧にする。

## 1. 範囲

**対象**

- 企画書のリリース1〜4で追加・変更する機能（Today の見直し、計画とルーティン、予定と教材、Journey）
- 追加する migration（0007〜0009）のテーブル、制約、トリガー、RLS、RPC、ビュー
- 変更の影響を受ける既存機能（タスクの操作、スコアの計算、振り返り、カレンダー）

**対象外**

- スマホでの表示（NFR-07。今回は対象外）
- 性能の数値測定。NFR-06 は受け入れテストで体感を確認するだけにする
- 複数ユーザーによる同時利用（個人利用のため）。ただし RLS による他人のデータの遮断は確認する

## 2. テストのレベル

| レベル | 手段 | 対象 | 実行のタイミング |
| --- | --- | --- | --- |
| 単体テスト（UT） | Vitest（`npm test`）。CIでも自動実行 | `src/lib/plans/logic.ts`、`src/lib/journey/logic.ts` の純粋関数 | 実装中に随時、PRごとにCI |
| DBテスト（DB） | 手動。SQLを実行し、結果を目で確認する | 制約、トリガー、RLS、RPC、ビュー | migration を追加するPRごと |
| 受け入れテスト（AT） | 手動。ブラウザで画面を操作する | 機能仕様書の画面仕様と業務ルール | リリースごとのPR |
| 回帰テスト（RT） | 手動＋既存の自動テスト | 既存機能が壊れていないこと | リリースごとのPR |

- 既存の自動テスト（`score.test.ts`、`date.test.ts`）と、CIの型検査・ビルドは、すべてのPRで通っていること
- DBテストは自動化しない（2026-09-29 決定）。手順をこの文書に残し、実行結果をPRに記録する

## 4. テストの観点

| 観点 | 例 |
| --- | --- |
| 正常系 | 仕様どおりの操作で、仕様どおりの結果になる |
| 境界値 | フェーズの開始日・終了日の当日、期日の前日・当日・翌日、文字数の上限、所要時間の5分と600分 |
| 状態の組み合わせ | 計画の4つの状態 × 生成の有無、教材の状態の循環、やりたいことの達成と取り消し |
| 冪等性・競合 | Todayを何度開いても、2つのタブで同時に開いても、ルーティンタスクは1つ |
| データ保全 | 過去の日のタスクとスコアが変わらない、既存の振り返りのメモが消えない |
| 権限 | 他のユーザーのデータを読めない・書けない、他人の計画に子の行を作れない |
| 空・多い | データが0件の表示、上限を超えたときの折りたたみ |
| 異常系 | 保存に失敗したときに入力が残る、存在しない計画のURL |

### 5.2 DBテスト（DB）

ローカルSupabase Studioの SQL エディタで実行する（接続URLは `supabase status` で確認する）。SQL エディタは管理者権限で動き RLS が効かないので、ユーザーとして実行するケースは次の形で包む。

```sql
begin;
set local role authenticated;
set local request.jwt.claims = '{"sub": "<テスト用ユーザーのID>", "role": "authenticated"}';
-- ここに確認したいSQLを書く
rollback;  -- 確認だけで変更を残さない場合
```

「今日」はテスト実施日。ケースの前提は 3.2 のテストデータ。

**ルーティンの生成（generate_routine_tasks）**

| ID | 前提・操作 | 期待結果 | 対応 |
| --- | --- | --- | --- |
| DB-01 | 今日の日付で実行 | 計画A（P1の英語）と計画B（web技術、平日のみ）のタスクだけができる。計画C（休止中）・D（構想中）はできない。戻り値は作った件数 | BR-01, BR-02 |
| DB-02 | 作られたタスクの中身を確認 | タイトル・重要度・`planned_minutes`・メモ（メニュー）・`plan_id`・`routine_id` がルーティンと一致し、時刻は NULL、未完了 | BR-02 |
| DB-03 | 同じ日付でもう一度実行 | 0件。タスクは増えない | NFR-04 |
| DB-04 | 2つの SQL エディタのタブで同時に実行 | 合計で1回分しかできない（一意インデックスで片方が何もしない） | NFR-04 |
| DB-05 | 土曜の日付で実行（範囲チェックに入る日で確認できない場合は、曜日を変えたルーティンで確認） | 平日のみのルーティンは作られない | BR-02 |
| DB-06 | フェーズの開始日当日と終了日当日の扱い（P1終了日＝今日＋1日、P2開始日＝今日＋2日で確認） | 今日＋1日はP1のルーティン、今日＋2日はP2のルーティン（範囲チェックの都合で、フェーズの日付を今日に合わせて動かして確認する） | BR-03 |
| DB-07 | 今日−2日、今日＋2日を指定 | どちらも例外になり、タスクは作られない | NFR-01 |
| DB-08 | 生成済みのルーティンタスクを削除してから、もう一度実行 | `routine_skips` に1行でき、タスクは作られない | BR-02 |
| DB-09 | 生成後にルーティンのメニューを変更 | 作成済みのタスクのメモは変わらない | BR-02 |
| DB-10 | 生成で作られたタスクのある日の振り返りを確認 | その日の `daily_reviews` のスコアが、タスクを含めて再計算されている（振り返りがある場合） | BR-10 |

## 7. 合格基準と記録

**リリースしてよい条件**

- そのリリースの単体テストがすべて成功し、CI（型検査・テスト・ビルド）が通っている
- そのリリースのDBテスト・受け入れテスト・回帰テストがすべて「OK」。「NG」が残っている場合は、修正するか、影響が小さい理由と後で直す Issue を記録して承認を得る
