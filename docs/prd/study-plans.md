## 背景と目的

NotionのStudy Managerで管理している長期の学習計画を、Strideに移して一元管理する。計画で決めた毎日のルーティンがTodayへ自動で入るので、毎日タスクを手で登録する手間がなくなる。

- **今の課題**：週以上の計画はNotion、毎日のタスクはStrideと分かれており、計画のルーティンを毎日手でTodayに登録している
- **目的**：試験対策や趣味の勉強の計画（フェーズ・目標・教材・ルーティン）をStrideで持ち、Todayへ自動で流す
- **あわせて行うこと**：Calendarを、過去の達成とやりたいことを見返せるJourney画面に置き換える。Todayのレイアウトも見直す
- **対象外**：Notionの学習ノート（study record）はNotionに残す

デザインモック：[docs/mocks/study-plans](../mocks/study-plans/README.md)

## 成功指標

リリースから4週間、学習計画の管理をStrideだけで回せていれば成功とする。

| 区分 | 指標 | 目標 | 測り方 |
| --- | --- | --- | --- |
| 主指標 | 計画のルーティンをTodayに手で登録した回数 | 0回 | 計画に紐づかない学習タスクがないか、週次で確認 |
| 主指標 | NotionのStudy Planとロードマップを更新した回数 | 0回 | Notionの最終更新日を確認 |
| 副指標 | 進行中の計画のルーティン実施率（直近14日） | 計測できること。目標値は運用しながら決める | Plansの実施マス |
| ガードレール | 月の平均スコア | リリース前の月と比べて大きく下がらない | Journeyの月平均 |

ガードレールは、ルーティンが自動で入ることで未完了タスクが増え、スコアが計画の立てすぎを映してしまう場合の備え。下がったら、ルーティンの時間や重要度を見直す。

## 機能要件

要件は番号で参照し、機能仕様書・テスト計画・Issueからこの番号を指す。優先度は Must（ないと目的を果たせない）と Should（あると便利）の2段階。振る舞いの詳細は機能仕様書に書く。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-01 | 学習計画を作成・編集・削除できる（名前、色、期日） | Must |
| FR-02 | 計画の状態を 構想中／進行中／休止中／完了 で切り替えられる | Must |
| FR-03 | 計画に目標（1行）と補足を書け、詳細画面で目立つように表示される | Must |
| FR-04 | 計画を期間付きのフェーズで区切れる。フェーズはなくてもよい | Must |
| FR-05 | フェーズごとに、所要時間・曜日・重要度・メニューを持つルーティンを設定できる | Must |
| FR-06 | 進行中の計画のルーティンが、その日のTodayにタスクとして自動で入る | Must |
| FR-07 | 自動で入ったタスクも通常のタスクと同じく採点され、重要度をその日だけ変えられる | Must |
| FR-08 | Todayで、計画から入ったタスクの計画名とメニューが分かる | Must |
| FR-09 | 計画に日付付きの予定を登録でき、当日のTodayに入る | Must |
| FR-10 | 予定にマイルストーンの印を付けられる | Should |
| FR-11 | 期限切れの予定が分かり、今日の予定に移せる | Should |
| FR-12 | 計画に教材を登録でき、未着手／使用中／完了と完了日が分かる | Must |
| FR-13 | 教材にリンクと関連フェーズを設定できる | Should |
| FR-14 | 計画一覧で、進行中の計画の進み具合（フェーズ、残り日数、直近の実施、次の予定）と今日の学習時間の合計が分かる | Must |
| FR-15 | 計画の詳細で、ルーティンの直近14日の実施状況が分かる | Should |
| FR-16 | 期日を過ぎた計画には完了を促す表示が出る | Should |
| FR-17 | やりたいこと（夢・気軽な目標）を登録し、達成したらチェックできる | Must |
| FR-18 | Journeyで、スコアのカレンダーと、達成の記録（計画の完了、やりたいことの達成、マイルストーン、教材の完了）を時系列で見られる | Must |
| FR-19 | Todayのタイムライン表示で、時刻未設定のタスクをタイムラインのすぐ横からドラッグできる | Should |
| FR-20 | Todayの指標（充実度・起床・就寝）と振り返り（ハイライト・明日の意図）を1枚の欄で入力でき、自動で保存される | Should |

## 非機能要件

最優先は、過去のスコアと記録を壊さないこと。

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | データ保全 | 新機能の追加やルーティンの自動生成で、過去の日のタスクとスコアが変わらない |
| NFR-02 | データ保全 | スコアの計算式とランクの境界は変えない |
| NFR-03 | データ保全 | 既存のデータ（レビューのメモを含む）は、画面から消えてもDBに残す |
| NFR-04 | 整合性 | 同じルーティンのタスクが同じ日に2つ以上できない（Todayを何度開いても、複数の端末で同時に開いても） |
| NFR-05 | セキュリティ | 計画・教材・やりたいことなど全データは、本人しか読み書きできない |
| NFR-06 | 性能 | ルーティンの生成でTodayの表示が体感できるほど遅くならない |
| NFR-07 | 対応環境 | PCのブラウザで使えること。スマホ対応は対象外（別の機会に全体をレスポンシブ対応する） |
| NFR-08 | デザイン | 既存のNotion風のダークテーマと見た目を揃える |

## 画面構成

新しい画面はPlans（一覧と詳細）とJourneyの2つ。Todayは今の画面を生かしたまま、レイアウトだけ整える。各画面の見た目は[デザインモック](../mocks/study-plans/README.md)を参照。

| 画面 | 主な内容 |
| --- | --- |
| Plans 一覧 | 今日の学習予定の合計（計画ごとの内訳）、進行中の計画カード（残り日数、フェーズの進捗、ルーティン、直近7日の実施、次の予定または期限切れ）、休止中・構想中・完了の一覧 |
| 計画の詳細 | 目標（計画の色で強調）、フェーズの帯と「今日」の線、選んだフェーズのルーティンと直近14日の実施、予定、教材 |
| Today | 今の画面をベースに、計画から入ったタスクに計画名とメニューを1行表示。レビューをスコアの欄に統合し、時刻未設定のタスクをタイムラインの隣に移す |
| Journey | 上部の統計（A/B連続、月の平均点、年の達成数）、スコアのカレンダー、やりたいこと、達成の記録 |

## リリース計画

4回に分けて出し、各回で使えるものを増やす。Notionとの二重管理が解消するのはリリース2の時点。

| リリース | 使えるようになること | 対応する要件 |
| --- | --- | --- |
| 1. Todayの見直し | 時刻未設定のタスクをタイムライン横からドラッグできる。振り返りがスコアの欄にまとまる | FR-19, FR-20 |
| 2. 計画とルーティン | 計画とフェーズを作り、ルーティンが毎日Todayに入る。英語・応用情報・web技術の計画を手入力で移す | FR-01〜FR-08, FR-14, FR-15 |
| 3. 予定と教材 | 計画に予定と教材を持てる | FR-09〜FR-13, FR-16 |
| 4. Journey | CalendarがJourneyに変わり、やりたいことと達成の記録が見られる | FR-17, FR-18 |

## 決まった論点

- [x] 休止中に期間が過ぎたフェーズ → 再開しても日付はそのまま
- [x] 計画の完了 → 期日を過ぎたら完了を促す表示を出す。完了にするのは手動
- [x] 計画の色 → 8色の固定パレット（ピンク・オレンジ・イエロー・グリーン・ティール・ブルー・パープル・グレー）
- [x] Journey上部の年の達成数 → 計画の完了とやりたいことの達成の2種類だけ数える
- [x] Notionからの移行 → 手入力
