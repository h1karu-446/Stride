# ADR-0006: 7日先までのメニューは、ボタンを押したときに前もって生成する

| 項目 | 内容 |
| --- | --- |
| ステータス | 承認済み |
| 日付 | 2026-10-23 |
| 関連 | [ADR-0002](0002-generate-routine-tasks-on-open.md) / [機能仕様書 BR-02](../specs/study-plans.md) / [技術設計書 4.6・6.1](../design/study-plans.md) / Issue #84 |

## 状況

ADR-0002 では、ルーティンタスクを「今日を開いたとき」だけ作り、RPC の日付をDBの日付の±1日に限った。
そのため、翌日以降の段取り（メニューに時刻を割り当てる、要らない分を外す）を寝る前に決められない。
計画の「予定」は日付付きのタスクなので未来の日にも出るが、メニュー由来のタスクだけが出てこない。

## 決定

- 未来の日の Today に「この日のメニューを出す」ボタンを置き、押したときだけ、同じ RPC `generate_routine_tasks(p_date)` で**本物のタスク**を作る。自動では作らない
- 出せるのは明日〜端末の今日+7日。RPC の上限は `current_date + 8`（日本時間の0〜9時はDBの日付が前日になるため1日足す）。下限 `current_date - 1` は変えない
- 生成条件・作られるタスク・二重生成の防止・スキップは今日の生成と同じものを使う

## 検討した案

| 案 | 概要 | 評価 |
| --- | --- | --- |
| A. ボタンで本物のタスクを作る（採用） | 今日の生成と同じ RPC を未来の日で呼ぶ | 時刻設定・削除（スキップ）・持ち越しなど既存の操作がそのまま使える。条件判定はDBの1か所のまま |
| B. 下書きだけ表示する | 保存せず、表示のたびにルーティンから組み立てる | 時刻を決めるには結局どこかに保存が要る。ADR-0002 の案Dと同じく、採点や実行マスとの整合が取りにくい |
| C. 未来の日を開いたら自動で作る | ボタンなしで生成する | 見に行っただけの日にもタスクができる。「必要なときだけ出したい」という要望に合わない |
| 上限を制限しない | どの未来の日でも作れる | 作った後にフェーズや計画を変えたとき、古いタスクが遠い日まで残りやすい |

## 影響

- 良くなること
  - 翌日〜1週間先のメニューを前もって並べ、時刻を決めておける
  - その日になって開いても二重に作られない（部分一意インデックス）。前もって削除した分は作られない（`routine_skips`）
- 引き受けるデメリット
  - 作った後でメニュー・フェーズ・計画を変えても、作成済みの未来のタスクは変わらない（「編集の反映」の規則と同じ）。不要なら手で削除する。計画の削除（`delete_plan`）では未来の未完了タスクとして消える
  - Today の画面は前もって削除した分を出さないよう、その日の `routine_skips` も読む（取得が1回増える。明日〜7日先の表示のときだけ）
