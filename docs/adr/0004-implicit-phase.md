# ADR-0004: フェーズを作らない計画には、暗黙のフェーズを1つ持たせる

| 項目 | 内容 |
| --- | --- |
| ステータス | 承認済み |
| 日付 | 2026-09-29 |
| 関連 | [機能仕様書 BR-03](../specs/study-plans.md) / [技術設計書 4.2・4.6](../design/study-plans.md) |

## 状況

計画には、試験対策のようにフェーズで区切るものと、web技術のように期限もフェーズもなく続けるものがある。企画の段階で「計画の種類は分けず、フェーズは任意にする」と決めた（FR-04）。一方で、ルーティンはフェーズごとに変わるので、フェーズに属させたい。

フェーズがない計画のルーティンを、どこにぶら下げるかを決める必要があった。

## 決定

計画を作ると、期間を持たない「暗黙のフェーズ」を1つ自動で作る。フェーズを作っていない計画のルーティンと教材の紐づけは、このフェーズに属する。最初のフェーズを追加したときは、暗黙のフェーズの行を通常のフェーズに更新して、ルーティンをそのまま引き継ぐ。最後のフェーズを削除したときは、暗黙のフェーズに戻す（`delete_phase`）。

## 検討した案

| 案 | 概要 | 評価 |
| --- | --- | --- |
| A. 暗黙のフェーズ（採用） | データ上は常に「計画 → フェーズ → ルーティン」 | 生成・表示・教材の紐づけの処理が1通りで済む。最初のフェーズの追加が行の更新だけで済む |
| B. ルーティンの親を2通りにする | `routines` に `plan_id` と `phase_id` の両方を持たせ、どちらかを入れる | 生成、実施マス、表示のすべてで「フェーズ経由か、直接か」の分岐が必要になる。フェーズを追加したときに付け替えも必要 |
| C. フェーズを必須にする | 計画を作るときに最低1つのフェーズを作らせる | 期限のない計画にも期間の入力を強いることになり、「種類を分けない」という企画の決定に反する |

## 影響

- 良くなること
  - 計画の種類を意識しなくてよい画面のまま、データの形を1通りに保てる
- 引き受けるデメリット
  - 画面では `is_implicit` を見て、フェーズの帯と見出しを隠す分岐が必要
  - 「暗黙のフェーズと通常のフェーズが同じ計画に並存しない」ことは、DB制約だけでは守りきれない。フェーズの追加は暗黙のフェーズの更新、削除は `delete_phase` に限ることで守る
