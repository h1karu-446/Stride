# ADR-0002: ルーティンタスクは、今日を開いたときに RPC で生成する

| 項目 | 内容 |
| --- | --- |
| ステータス | 承認済み |
| 日付 | 2026-09-29 |
| 関連 | [機能仕様書 BR-02](../specs/study-plans.md) / [技術設計書 4.6・6.1](../design/study-plans.md) |

## 状況

進行中の計画のルーティンを、毎日Todayにタスクとして入れる（FR-06）。条件は「進行中の計画」「今日を含むフェーズ」「曜日が合う」「スキップされていない」の組み合わせで、1日1回だけ作る必要がある（NFR-04）。過去の日に作ると過去のスコアが変わるので、作ってはいけない（NFR-01）。

いつ、どこでタスクを作るかを決める必要があった。

## 決定

Todayで「今日」の日付を表示したときに、画面から RPC `generate_routine_tasks(p_date)` を呼んで作る。関数の中で条件に合うルーティンを1回の `insert ... select` で登録し、`tasks (routine_id, scheduled_date)` の部分一意インデックスと `on conflict do nothing` で二重生成を防ぐ。`p_date` はDB側の日付の±1日に限る。

## 検討した案

| 案 | 概要 | 評価 |
| --- | --- | --- |
| A. 開いたときに RPC（採用） | 条件判定と登録をDBの関数で1回に行う | 往復が1回。条件判定がDBに1か所だけあり、二重生成もDBで防げる。端末の「今日」をそのまま使える |
| B. 開いたときに画面から insert | 画面で対象のルーティンを判定し、複数の insert を送る | 条件判定が画面に散らばる。複数タブで同時に開くと、判定と登録の間に競合が起きやすい |
| C. 毎日決まった時刻に定期実行 | pg_cron や Edge Function のスケジュールで0時に生成する | ユーザーのタイムゾーンの「0時」を扱う必要がある。実行基盤の設定と監視が増える。開かない日にもタスクが作られ、その日のスコアが下がる |
| D. 生成せずに表示時に合成 | 実体を作らず、表示のたびにルーティンからタスクを組み立て、完了時に実体化する | スコア計算は `tasks` しか見ないので、未完了のルーティンが採点に入らない。カレンダーや実施マスとの整合も取りにくい |

## 影響

- 良くなること
  - 定期実行の基盤が要らず、Supabase の既存の構成だけで完結する
  - 何度開いても、複数の端末で同時に開いても、タスクは1つしか作られない
- 引き受けるデメリット
  - Todayを開かなかった日は、ルーティンタスクが作られない。その日は実施マスで「対象外」になり、スコアにも含まれない。Todayを開かない日は記録自体をしない運用なので許容する
  - 開いた直後は、ルーティンタスクが数百ミリ秒遅れて一覧に加わる
  - 端末の日付を信用するため、範囲チェック（±1日）で過去・遠い未来の生成だけを防ぐ
