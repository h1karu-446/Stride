# ADR-0001: 予定は tasks テーブルの1行として持つ

| 項目 | 内容 |
| --- | --- |
| ステータス | 承認済み |
| 日付 | 2026-09-29 |
| 関連 | [機能仕様書 BR-04](../specs/study-plans.md) / [技術設計書 4.2](../design/study-plans.md) |

## 状況

計画に「8/13 TOEIC申込」「9/30 模試」のような日付付きの予定を持たせる（FR-09）。予定は当日のTodayに出して、Todayで完了にしたい。完了したマイルストーンはJourneyの達成の記録にも載せる。

予定の置き場所として、専用のテーブルを作るか、既存の `tasks` を使うかを決める必要があった。

## 決定

予定用のテーブルは作らず、`tasks` の1行として保存する。計画との紐づけは `tasks.plan_id`、マイルストーンの印は `tasks.is_milestone` で持つ。予定を作った時点で、その日付のタスクがDBに入る。

## 検討した案

| 案 | 概要 | 評価 |
| --- | --- | --- |
| A. tasks の1行（採用） | `plan_id` 付きのタスクとして保存する | 完了状態が1か所にしかない。生成処理が要らない。既存のタスク操作（編集、重要度、時刻、完了）とスコア計算がそのまま使える |
| B. 予定テーブル＋当日に生成 | `schedules` テーブルに持ち、当日にタスクを生成して紐づける | 予定とタスクの2か所に完了状態ができ、同期が必要になる。生成処理も増える |
| C. 予定テーブル＋Todayで合成表示 | 別テーブルのまま、Todayで tasks と並べて表示する | Todayが2種類のデータを扱うことになり、スコア計算（`tasks` だけを見る）に含まれない |

## 影響

- 良くなること
  - Todayで完了にするだけで、計画の詳細とJourneyにも反映される
  - スコア計算、既存のタスク操作、既存のトリガーに手を入れずに済む
- 引き受けるデメリット
  - `tasks` に計画用の列（`plan_id`、`is_milestone`）が増え、手動のタスクでは使わない列を持つ。NULL可・既定値ありにして影響を抑える
  - 未来の日付のタスクが事前に `tasks` に入る。Todayで未来の日付を開くと予定が見えるが、これは仕様どおり
  - 「予定の日付は今日以降」（BR-04）は、DB制約ではなく画面の入力チェックで守る。既存の手動タスクには過去の日付を許しているため、テーブル全体の制約にはできない
